# Golt mobile development and release guide

This is the repository-specific checklist for running the Expo app, connecting
it to the Python API, testing on a phone, and creating signed builds.

## What is already configured

- Expo SDK 57 with React Native 0.86 and React 19.
- Native video playback through `expo-video`.
- Push-notification registration through `expo-notifications`.
- Authenticated realtime messages through the backend `/realtime` WebSocket.
- Mobile feed, profiles, direct messages, and groups/community screens.
- iOS bundle identifier and Android package: `com.golt.mobile`.
- EAS profiles for iOS Simulator, internal preview, and production builds.

## Local configuration

Copy `.env.example` to `.env` and change only the values needed for your
environment. `.env` is intentionally ignored by Git.

`EXPO_PUBLIC_*` values are compiled into the app and are not secrets. Never put
private keys, client secrets, database passwords, or server credentials there.

For a phone on the same private Wi-Fi, either leave the API address at
`localhost` and let the app replace it with Expo's detected computer address,
or use the computer's current LAN address explicitly. Start the backend with:

```powershell
python -m uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

Before opening Expo, verify `http://<computer-ip>:8000/health` in the phone's
browser. If the phone cannot open that URL, the app cannot reach the API.

Start the app from this directory:

```powershell
npm install
npx expo start --clear --lan
```

Use `npx expo start --clear --tunnel` only when the phone cannot reach Metro
over LAN. An Expo tunnel exposes the JavaScript bundle, not the Python API. A
restricted network still requires a separately deployed or securely tunneled
HTTPS API and a matching `wss://` realtime address.

## Validation before every push

```powershell
npm run typecheck
npx expo config --json
npx expo export --platform android --output-dir outputs/android
git diff --check
```

## Link the app to Expo/EAS

The repository can be configured without creating an Expo account on somebody
else's behalf. A project owner must perform the one-time account operation:

```powershell
npx eas-cli@latest login
npx eas-cli@latest init
```

Keep the project ID generated by Expo in the app configuration. For local push
testing, it can also be supplied as `EXPO_PUBLIC_EAS_PROJECT_ID`.

## Builds

```powershell
# iOS Simulator
npx eas-cli@latest build --platform ios --profile simulator

# Internal Android APK or signed iOS device build
npx eas-cli@latest build --platform android --profile preview
npx eas-cli@latest build --platform ios --profile preview

# App-store builds
npx eas-cli@latest build --platform android --profile production
npx eas-cli@latest build --platform ios --profile production
```

iOS device/TestFlight builds require Apple Developer access. Google Play
submission requires Google Play Console access. Production builds must use a
public HTTPS API and `wss://` realtime endpoint; they cannot connect to a
developer's laptop.

## Fast diagnosis

- **App does not load:** restart Expo with `--clear`; try tunnel mode only for
  Metro connectivity.
- **API request fails:** open `/health` from the phone and check the backend
  terminal before debugging login details.
- **Realtime reconnects:** verify the WebSocket URL, token, reverse-proxy
  upgrade support, and `ws://` versus `wss://` protocol.
- **Push says configuration is needed:** link the EAS project and provide its
  project ID; use a physical device and a signed development/preview build for
  complete push testing.
- **Build requests credentials:** use the company-owned Apple, Google, and Expo
  accounts. Do not create or store personal signing credentials in Git.
